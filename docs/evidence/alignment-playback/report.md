# 对齐预览播放停在第一帧

用户报告对齐工作台“播放”点击后人物不动。该窗口的计时effect依赖整个frames数组；主编辑器每次渲染都会重新构造该数组。后台主播放不断更新时，工作台的41.7ms计时器在触发前反复被清除。此外，后端单帧预览原先通过composeInputs读取整段RGBA文件，增加每次切帧的载入开销。

修复：制作帧列表按timeline记忆；播放计时依赖当前帧身份、时序及图像就绪状态，父组件数组变化不重置计时。当前图像加载完成后才推进下一帧；出错时暂停并提示，等待期间显示载入状态。composeInputs增加内部可选frameId，预览只校验和处理指定RGBA，保留原序列索引；完整预检和导出仍解析全部帧。

有限验证：

- 隐藏Electron窗口使用真实AlignmentWorkshop，父组件每16ms重绘，每张PNG延迟150ms。修复前1.4秒只停在1/3；修复后访问1/3、2/3、3/3并实际加载三张不同固定PNG，无写请求。[修复前](before/layout.json)、[修复后](verified/layout.json)。这属于隔离组件验证，不是用户当前窗口的录屏。
- `bun test tests/pipeline/preview-inputs.test.ts`：1项通过。指定第二帧仅返回一个输入，原序列索引仍为1，与完整解析对应输入相同。
- `bun run typecheck`：退出0。

50%显示倍率下预览画布256×320，人物站定基准约240像素。首次冷预览可能等待后端生成当前PNG；此次验证不构成实际24fps吞吐保证。Windows后台加载启动时的前端bundle，用户保存并关闭窗口后，通过同一批次“重启并打开人工审核.cmd”加载新版。
