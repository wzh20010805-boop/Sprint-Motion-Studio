# P1 真实 PNG 检查

日期：2026-10-10。样例为本机编码的合成 SDR H.264 视频，不是用户的小兵动作素材。

使用隔离 `.venv-image` Python 3.11.9 / Pillow 12.0.0，通过 `probes/inspect-png.py` 对完整原始帧逐个 `Image.load()`，再生成棋盘格 contact sheet。目录映射见 `extraction-matrix.json`。

| 源显示帧 | 实际 PNG | 尺寸 | 解码 | 完全不透明 | 空图 |
|---:|---:|---|---|---:|---:|
|48|48|64×48，一致|全部通过|48|0|
|61|61|64×48，一致|全部通过|61|0|
|120|120|64×48，一致|全部通过|120|0|
|300|300|64×48，一致|全部通过|300|0|

报告和成图在 `png-check-48/`、`png-check-61/`、`png-check-120/`、`png-check-300/`。协调代理已打开48和300帧检查图，所有索引连续。棋盘格显示在缩略图外围的空画布区域，**不表示视频背景已去除**。实际 PNG 为 RGB，转换到 RGBA 后 Alpha 全为255。

这批验证的结论是完整抽帧、连续索引、尺寸和解码成功。未执行场景抠图，因此背景透明、武器缺失、身体变形、头发边缘、角色位置对齐等美术问题均未验收。不能使用这些原始帧作为“已审核透明动作”发布。

重复画面和真实 VFR 有独立真实媒体回归测试，详见 `extraction-report.md`。重复帧保留原显示时长；异常输入、取消和缓存损坏均须失败或显式报告。P2 需要一段获授权的真实角色视频及人工参考帧，才可判断 Rembg 是否满足质量目标。
